# 0xELF: Reverse Engineering Framework for Flexo-Generated Weird Machines

This repository contains the code of 0xELF, a reverse engineering framework
capable of extracting the hidden computation performed by Flexo-generated
microarchitectural weird machines in the form of a combinational circuit.

# Prerequisites

0xELF needs a virtual environment initialized with the packages present in the `requirements.txt` file.
In order to generate one, run from the project's directory:

```python
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Flexo

The Flexo compiler is not necessary for the 0xELF workflow, however, you need to have a binary compiled using Flexo to be used as an input for 0xELF.
If you need the Flexo compiler, follow these instructions:

1. If you didn't do already, fetch the submodules for this repository
(either by cloning this repo using `git clone --recurse-submodules` or by running `git submodule update --init --recursive` after cloning).
2. Compile Flexo as described in the repository (using `docker` or `podman`)
3. We provide the `flexo-compile.sh` script that allows to use the compiled version of Flexo in the `Flexo/` directory to compile weird machines.
In order to set variables for Flexo, use shell variables (e.g., `WR_OFFSET=512 ./flexo-compile.sh`).
4. The ground truth generated by Flexo (i.e., the circuit files used for generating the WM) will be placed in the `Flexo/tmp` directory.

## abc

abc is a tool that allows to check if a circuit extracted from 0xELF is equivalent to the one generated by Flexo.

1. If you didn't do already, fetch the submodules for this repository
(either by cloning this repo using `git clone --recurse-submodules` or by running `git submodule update --init --recursive` after cloning).
2. Compile `abc` following the instructions in the repository
3. Run 0xELF on a Flexo-generated binary
4. Rename the variables in the BLIF that 0xELF outputs so that they match the ones of the Flexo ground truth.
5. Run `abc` and issue the command `cec <renamed_0xELF_output> <Flexo_ground_truth>`

# 0xELF Quickstart

To use 0xELF, you must first create a new python virtual environment (`python -m venv .venv`), activate it (bash: `source .venv/bin/activate`) and install the prerequisites (`pip install -r requirements.txt`).
0xELF is located in the `reveng` directory (`cd reveng`).

0xELF can be run by using the command `./oxelf.py`.
0xELF supports three subcommands, two of which (`disass` and `info`) only serve as helpers.

## `analyze`

The `analyze` subcommand runs 0xELF on a target binary.
Its syntax is:

```
./oxelf.py [--seed SEED] analyze [--iz] [--arguments ARGUMENTS] start_address elf_file
```

where `elf_file` is the target binary and `start_address` is the address of a Flexo Weird Function in the binary.
The default format for `start_address` is an integer (even in base 16 if it begins with `0x`), but for convenience the interface can also accept the name of a symbol if the target binary is not stripped.
`--iz` enables the *Ignore leading zeros* described in the paper.
`--arguments` provides an upper bound on the number of its parameters (that is, the function cannot have more parameters than `--arguments`); by default `--arguments` is 6, increasing it will create multiple angr symbols, each one representing a function parameter.
`--seed` can be set to a fixed integer if 0xELF must behave deterministically.
Basically, this fixes the `negated` assignment as described in the paper, so that the output will always be the same.

The resulting BLIF is output on `stdout`, while debugging information is printed on `stderr`.
If you want to collect such outputs, use redirects accordingly (e.g., for bash append `> outputfile.blif 2> debug0xELF.txt`).

## `info`

The `info` subcommand is used for extracting useful information from the binary.
Currently, it supports only listing the symbols present in the binary:

```
./oxelf.py info --list-symbols elf_file
```

## `disass`

The `disass` subcommand is useful for disassembling the entire binary and finding the `start_address` of the target Flexo Weird Function:

```
./oxelf.py disass elf_file
```

Since the output will probably be very long, pipe the output into a pager (e.g., `./oxelf.py disass elf_file | less`).

## Full Example

In this example, we target the 8-bit adder included in the examples of Flexo.
Ensure you have podman installed; if you prefer to use docker, change `podman` into `docker` in the script `flexo-compile.sh`.

1. Compile Flexo and abc as described above
2. Create a new directory for the test: `mkdir test`
3. Copy the source files in the `test` directory: `cp ref/Flexo-dual/02-adders/{test_adder_8.cpp,macro.h} test/`
4. Run `./flexo-compile.sh test/test_adder_8.cpp test/macro.h`
5. The compiled binary should be in `./test`
6. Copy the ground truth from Flexo: `cp Flexo/tmp/_Z15__weird__adder8PhS_S_S_.blif test/ground_truth.blif`
7. Run `./reveng/oxelf.py info --list-symbols ./test/test_adder_8.elf | grep __weird__` to get the starting address of the Flexo Weird Function (note that this step is not necessary if other tools, like Ghidra, can be leveraged to find the starting point of the weird function).
8. Optionally strip the binary `strip -s ./test/test_adder_8.elf`
9. Run `./reveng/oxelf.py analyze <starting_address> ./test/test_adder_8.elf > ./test/output.blif`
10. Rename outputs to match the Flexo ground truth: `sed -i 's/_in1/_in2/g; s/_in0/_in1/g; s/_out2/_out/g' ./test/output.blif`
11. Run `./abc/abc`
12. Run `cec ./test/output.blif ./test/ground_truth.blif`, the output should be `Networks are equivalent.`

## Caveat

For compiling the AES examples the `./flexo-compile.sh` script is not enough: follow the instructions provided in the Flexo repository.
